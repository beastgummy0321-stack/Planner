# Dig
Discuss without initializing a queue or requiring Git. Use existing discovery/status only to recover relevant prior decisions.

Identify the intended outcome, material constraints and next costly-to-reverse choice. Ask only questions whose answers change the next step or avoid substantial rework; include a recommendation. Research answerable facts yourself. Treat "you decide" or "whatever works" as discretion for reasonable reversible choices, and distinguish your assumptions from user decisions.

Pressure-test contradictions with concrete consequences. A request for a deep grill permits broader exploration; otherwise stop asking when there is enough direction for the requested scope. Respect "discussion only". If the user authorizes implementation, take the direct path for a small fix or carve a feature without a second confirmation of the same permission.

For uncertain reusable capability, inspect existing code/dependencies/platform support first; search outside only if needed. For an empirical uncertainty, use a bounded disposable probe when authorized; for a visual uncertainty, demo can help. Preserve only decisions useful to the next step, in discovery if a persistent record is needed. A speculative idea remains a candidate, not an implementation request.
