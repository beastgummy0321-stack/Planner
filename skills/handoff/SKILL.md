# Handoff
Save when requested; suggesting a new session does not authorize creating it or interrupting work. Mention a handoff only at a safe point with a concrete benefit, after the outcome; respect declined reminders.

Use the open feature's Outcome/Decisions, or discovery if no feature exists. Read the carrier before merging changes. Preserve only confirmed constraints, agent choices, unresolved questions, rejected routes with reasons, verified/unverified progress, running job identifiers and the next step. Do not save credentials. Without a project, provide the concise record in the reply.

Read back the affected carrier once; status should locate it. Use the current host's new-session/resume facility. Do not assume a Claude command or that a hook is installed. If state is not injected, run status once on resume. Check only what the next step depends on. Another session or unknown background job may still be alive; recover only after confirming termination. The latest user request controls whether to continue, and saved state never expands authority.
