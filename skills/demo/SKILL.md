# Demo
Build one focused fake-data UI prototype covering the uncertain interaction. Reuse existing design language from relevant tokens/components/screens. Do not audit unrelated UI or build every possible flow.

Use `.harness/scratch/prototype/<slug>/index.html`, or a temporary directory if no harness exists; no Git/init prerequisite. Default to self-contained HTML/CSS/JS that opens directly. A dev preview is acceptable when the interaction requires it. Use realistic deterministic data and no production APIs or credentials. Keep revisions in the same prototype; make alternatives only when requested.

Build locally or delegate with the prototyper role when that saves context. Installed design skills are optional capabilities: at most one direction and one useful critique pass. Skip unavailable skills. Check the relevant rendered flow with available browser tools; otherwise disclose that it was not visually verified.

Report the usable preview path and the choices still open to the user. Record approved choices only when needed by a subsequent implementation. Approval of appearance does not itself authorize backend, payment or production work.
